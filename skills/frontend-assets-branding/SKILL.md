# Frontend assets and branding

Assets should make the product more specific and more usable.

## Images and media

- Use real or generated bitmap imagery when the user needs to inspect a product, person, place, state, or gameplay.
- Avoid dark, blurred, generic stock imagery when the subject needs to be understood.
- Match image treatment to the product: cropping, aspect ratio, color grade, filters, grain, borders, and captions should feel intentional.
- Use stable dimensions and responsive sources to prevent layout shift.
- Provide alt text that describes the image's job in the interface.
- Use image trails, reveal shaders, masks, and hover zoom only when images are central to the experience.

## Icons and SVGs

- Use the project's existing icon system. Do not mix icon families casually.
- Use familiar symbols for common actions: save, search, filter, download, edit, delete, undo, redo, close, expand, collapse.
- Keep icon stroke width, optical size, and alignment consistent.
- Use custom SVGs for diagrams, brand marks, game assets, technical schematics, and subject-specific visual language.
- Do not create fake logos or badges that imply real certification, partnership, or trust.

## Brand details

- Add or preserve favicon and metadata when building public-facing pages.
- Use brand voice in labels, empty states, and errors, but do not sacrifice clarity.
- Patterns, aurora, blobs, matrix backgrounds, gradients, filters, and ambient effects need a reason tied to the subject or state.
- Prefer one recognizable brand signature over many unrelated decorative tricks.

## Avoid

- Reusing the same avatar, logo, or generic illustration for different entities.
- Placeholder company names, fake testimonials, and lorem ipsum.
- Decorative SVG noise that bloats the DOM or hurts performance.
- Background effects that compete with text or controls.
